## 一、概述

自选组合是用户自定义的概念板块，每个组合包含若干股票，系统实时计算组合指数、估值统计和个股行情，提供类似行业板块的看板体验。

### 设计原则

- **不建新表**：组合配置存 JSON，数据全走现有 `daily_bar` 表实时聚合
- **实时计算**：组合数量少（几只到几十只），聚合毫秒级，无需预计算缓存
- **零侵入**：不影响现有模块，仅新增 `watchlist_tools.py` + Streamlit 页面

## 二、数据模型

### 2.1 组合配置 — JSON 文件

路径：`data/watchlist.json`

```json
{
  "spacex概念": {
    "description": "太空探索相关产业链",
    "created_at": "2026-05-06",
    "stocks": [
      {"code": "sh.600118", "note": "火箭发动机", "added_date": "2026-05-06"},
      {"code": "sz.002465", "note": "卫星通信", "added_date": "2026-05-06"}
    ]
  },
  "AI算力": {
    "description": "算力基础设施",
    "created_at": "2026-05-07",
    "stocks": [
      {"code": "sh.603019", "note": "GPU", "added_date": "2026-05-07"},
      {"code": "sz.300449", "note": "光模块", "added_date": "2026-05-07"}
    ]
  }
}
```

说明：
- 顶层 key 是组合名称，天然唯一
- `stocks` 是有序列表，前端展示顺序以此为准
- `note` 是用户备注，如"火箭发动机"、"卫星通信"，帮助记忆为什么选这只股
- 一个 JSON 文件管理所有组合，读写简单

### 2.2 时序数据 — 复用 `daily_bar` 表

不新建表。所有行情数据（收盘价、涨跌幅、PE_TTM、PB_MRQ 等）已在 `daily_bar` 中，通过 SQL 查询实时聚合。

### 2.3 为什么不建 `watchlist_index` 表

| 考量 | 分析 |
|------|------|
| 数据量 | 一个组合一般 5-30 只股，1 年约 250 天，查询聚合毫秒级 |
| 对比排行榜 | 排行榜慢是因为 4000+ 全市场股票；自选组合是十只级别，量级完全不同 |
| 成分变动 | 改 JSON 即可，无需决定"是否重算历史" |
| 维护成本 | 不需要"谁来更新、何时更新"的逻辑 |
| 扩展性 | 如果以后组合数量激增或需要秒级响应，再加表做缓存，改动不大 |

## 三、组合指数算法

### 3.1 等权指数法

```
基期：组合最早数据日，基点 = 1000

每日指数 = 前日指数 × (1 + 当日等权收益率)
当日等权收益率 = Σ(成分股当日涨跌幅) / N
```

处理细节：
- **停牌股**：收益率 = 0（等价于前值填充），分母 N 不变
- **新股/退市**：仅在有效交易日纳入计算，N 取当日实际有效股数
- **复权**：直接用 `daily_bar` 的 `pctChg` 字段，已含除权除息，指数天然是复权指数

### 3.2 计算流程

```python
def calc_group_index(group_name, start_date, end_date):
    """
    1. 读 JSON 拿成分股 code 列表
    2. SQL: SELECT date, pctChg FROM daily_bar 
       WHERE code IN (...) AND date BETWEEN ... AND ...
    3. 透视图（date × code），停牌填充 0
    4. 每日等权收益率 = mean(pctChg) / 100
    5. 累乘 × 1000 → 指数序列
    """
```

### 3.3 为什么选等权而非市值加权

| | 等权 | 市值加权 |
|---|---|---|
| 适合场景 | 概念板块、主题投资 | 宽基指数（沪深300等） |
| 含义 | 每只股同等重要，反映"整体热度" | 大盘股主导，反映"头部表现" |
| 计算 | `mean(pct_chg)`，简单 | 需每期重新算权重 |
| 参考 | 中证等权指数系列 | 上证50、沪深300 |

对于"spacex概念"这类主题组合，等权更合理——关注的是概念整体热度，不是谁市值大。

## 四、估值统计

```python
def calc_group_valuation(group_name, date):
    """
    1. 读 JSON 拿成分股
    2. SQL: SELECT peTTM, pbMRQ FROM daily_bar 
       WHERE code IN (...) AND date = ?
    3. 排除 peTTM < 0 的亏损股
    4. 计算 pe_mean, pe_median, pb_mean, pb_median
    """
```

展示内容：

| 指标 | 说明 |
|------|------|
| PE_TTM 均值 | 排除亏损股后的算术平均 |
| PE_TTM 中位数 | 更抗极值干扰 |
| PB 均值 | 全量计算（PB 负值较少见） |
| PB 中位数 | 同上 |
| 有效成分数 | peTTM > 0 的股票数 / 总数 |

## 七、性能预估

| 场景 | 数据量 | 预估耗时 |
|------|--------|----------|
| 主页（5个组合概览） | 5×10只×1行 | ~20-30ms |
| 详情页（指数1年） | 10只×250天 | ~10ms |
| 详情页（估值） | 10只×1行 | ~2ms |
| 详情页（个股行情） | 10只×1行 | ~2ms |

对比排行榜（4000+只全市场聚合）的秒级耗时，自选组合场景完全不需要缓存。

如果未来组合数量 > 50 或单组合 > 100 只，可以引入 `watchlist_index` 预计算表做缓存，届时改动仅新增一张表 + 更新逻辑，现有接口不变。
